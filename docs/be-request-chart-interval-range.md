# BE 요청: 차트 `interval`·`range` 파라미터 추가 + 지표 간격별 재계산

대상 엔드포인트: `GET /v1/stocks/{ticker}/indicators`
요청자: FE(안드로이드). 작성일: 2026-06-17.

## 배경

FE 차트는 두 축을 분리해 제어한다.

| 컨트롤 | 역할 | 값 |
|---|---|---|
| 봉 세그먼트 (interval) | 캔들 하나가 며칠치냐 | `일봉 · 주봉 · 월봉` |
| 기간 칩 (range) | 얼마나 멀리 거슬러 보냐 | `1개월 · 3개월 · 6개월 · 1년 · 전체` |

현재 이 엔드포인트는 **일봉 ~120개 고정 시리즈**만 반환한다(파라미터 없음). 그래서 FE가 일봉을
클라에서 `chunked`로 묶어 주/월봉을 흉내내고 있는데, 이 방식은 **지표(EMA·RSI·볼린저·스토캐스틱·
이격도)가 간격에 맞게 재계산되지 않아 값이 틀린다.** 그래서 FE는 현재 주/월봉에서 오버레이를 강제로
끄고 있다. 정상화하려면 BE가 간격·범위를 받아 그 간격 기준으로 캔들·지표를 모두 계산해 내려줘야 한다.

## 요청 1 — 쿼리 파라미터 추가

```
GET /v1/stocks/{ticker}/indicators?interval={1d|1w|1mo}&range={1m|3m|6m|1y|max}
```

- `interval`: 캔들 집계 단위. 기본 `1d`. (일봉/주봉/월봉)
- `range`: 조회 범위(거슬러 볼 기간). 기본 `6m`.
- 응답 스키마는 **기존 `IndicatorSet` 그대로 유지**. 단 내용물이 요청 간격·범위 기준이어야 한다.
  (FE DTO·매퍼 변경 없음, 쿼리 파라미터만 추가됨)

## 요청 2 — 간격 기준으로 전체 시리즈 재계산

반환되는 모든 배열은 **요청 `interval`로 집계된 캔들 인덱스에 정렬**되어야 한다.

- `candles`: 해당 간격의 OHLCV (예: 주봉이면 주 단위 시·고·저·종, 거래량 합)
- `rsi14`, `rsiSeries`, `ema5/20/60/120`, `bollingerUpper/mid/lower`, `stochasticK`/`stochasticD`,
  `disparitySeries`: **그 간격 캔들 위에서 다시 계산**한 값 (일봉 지표를 묶는 게 아니라 재계산)
- `crossMarkers`, `divergenceMarkers`: 해당 간격 캔들 인덱스 기준

## 요청 3 — 범위별 충분한 원천 데이터

주/월봉 + 1년/전체가 의미 있으려면 일봉 원천이 그만큼 길어야 한다. 워밍업(EMA120 등)을 포함해
`range`보다 넉넉히 확보한 뒤 잘라서 반환한다. (현재 "최근 120 거래일" 기본값 확장 필요)

## 완료 후 FE 작업

BE 반영되면 FE는 클라 측 `takeLast(days)` 윈도잉과 `chunked` 집계를 제거하고, 받은 시리즈를
그대로 그린다. 또한 주/월봉에서 막아둔 EMA·볼린저 오버레이를 다시 켠다.
